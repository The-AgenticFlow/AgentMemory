## What We Build: "EngramAgent"

A production-ready MemoryAgent that implements the engram-based memory architecture from `docs/agent-memory.md`, powered by Qwen Cloud models.

### Core Agent Concept

A **personal research assistant** that:
- Remembers every paper, document, and conversation across sessions
- Synthesizes findings from prior interactions without re-asking
- Proactively surfaces relevant context when it detects related queries
- Forgets outdated information gracefully (timely forgetting)
- Recalls critical memories within limited context windows
- Gets smarter over time as schemas consolidate from repeated experiences

This directly maps to the hackathon's Track 1 project idea: *"A research assistant that remembers every paper it has read and can synthesize findings across sessions."*

## Architecture Mapping: From Docs to Implementation

The 13 chapters from `docs/agent-memory.md` map to PocketFlow-Rust Nodes and Flows.

### PocketFlow-Rust Core Concepts

PocketFlow models agent logic as **directed graphs of Nodes** connected by **state-based edges**:
- **Node trait**: `prepare() → execute() → post_process()` lifecycle, returns `ProcessResult<State>`
- **ProcessState**: Enum variants control flow branching (Success/Failure/Default or custom)
- **Context**: Shared `HashMap<String, Value>` carrying data between nodes
- **Flow**: Graph runner that executes nodes in sequence based on state transitions
- **build_flow!** macro: Declarative flow construction

This maps naturally to the engram architecture: each pipeline component is a Node, and state transitions route episodes through the memory system.

### Flow Topology

The system is composed of **4 main flows** that run independently:

#### Flow 1: Ingestion Flow (per Episode)
```
EpisodeInput → ThalamusFilter → [Accepted] → BufferIngest → PatternSepComp → EngramCreate/Update
                            → [Rejected]   → Discard
```

#### Flow 2: Consolidation Flow (triggered by session end / schedule)
```
ConsolidationTrigger → BufferDecay → EngramDecayArchive → SchemaCompression → Done
```

#### Flow 3: Retrieval Flow (per query)
```
QueryInput → SchemaActivation → EngramCandidates → AssociativeSpreading → ConstructiveAssembly → ResponseOutput
```

#### Flow 4: Agent Loop Flow (main chat loop)
```
UserInput → RetrievalFlow → LLMGenerate → EpisodeCapture → IngestionFlow → ResponseOutput
```

### Module 1: Core Data Structures (`src/models/`)
- **Episode** — `{action, context, outcome}` + session_ref
- **Engram Dictionary Entry** — `{id, embedding, tags, strength, thalamus_scores, created_at, last_accessed, access_count, session_ref, kinship_ref, source, status, episodic_content_ref, schema_refs}`
- **Pattern Entry** (Pre-Engram Buffer) — `{pattern_hash, embedding, occurrences, strength, first_seen, last_seen, context_tags, threshold, decay_rate, source}`
- **Meta-Engram** (Schema Store) — `{id, embedding, tags, strength, source_engram_ids, prediction_fields}`
- **Session** — `{current_expectation, current_mode, task_context}`
- **Working Context** — `{goal_stack, active_engrams, episodic_buffer, inference_layer, context_metadata}`

### Module 2: Thalamus Filter Node (Ch. 2)
- Input gate: evaluates each Episode before it enters the memory system
- 4 parallel scores: Novelty, Surprise, Task-Relevance, Emotional Valence
- Relevance threshold modulation: Exploration (low), Routine (high), Critical (zero)
- Clarification: this is a **relevance score threshold** (`score >= threshold → Accepted`), distinct from the Pattern Sep/Comp **completion similarity threshold**
- Implementation: lightweight rule-based scorer + Qwen structured output for valence
- **Node mapping**: `execute()` computes scores, `post_process()` returns `Accepted`/`Rejected` state

### Module 3: Pre-Engram Buffer Node (Ch. 4)
- Dual role: episodic short-term storage + pattern accumulator
- ANN-based pattern matching in a dedicated Qdrant `pre_engram_buffer` collection
- Pattern metadata (`strength`, `occurrences`, timestamps, tags, threshold, decay_rate, source) stored as Qdrant payload; large episodic content still points to OSS/PostgreSQL refs
- Accumulation logic: strength increases on repeat, weighted by Surprise Score
- Decay: `strength * e^(-decay_rate * days_inactive)`, modulated by valence/surprise
- Size management: decay primary, LRU eviction as safety net
- **Node mapping**: `execute()` checks for existing pattern, `post_process()` accumulates or creates new entry

### Module 4: Pattern Separation / Completion Node (Ch. 5)
- ANN search in Engram Dictionary via Qdrant
- Completion threshold with 5-level modulation: mode, age, surprise, similarity gradient, adaptive feedback
- Completion threshold convention: `max_similarity > completion_threshold → Completion`; therefore **higher threshold = more Separation**, **lower threshold = more Completion**
- Kinship references (Depth-1) for associative retrieval
- Conflict resolution: strength-based winner-takes-all
- **Node mapping**: `execute()` performs ANN search, `post_process()` returns `Separation`/`Completion` state

### Module 5: Nightly Consolidation Run Flow (Ch. 6)
- 3 phases as 3 sequential nodes in a flow
- Session-based trigger (primary), threshold-based (overflow), time-based (fallback)
- Strength-proportional replay for borderline buffer entries
- Incremental schema compression (only new engrams + nearest neighbors)
- Quality control: reversible compression, adaptive feedback loop

### Module 6: Schema Store / Meta-Engrams Node (Ch. 7)
- Three integration modes: Assimilation, Accommodation, Schema Violation
- Schema as prediction engine for retrieval scope restriction
- Schema evolution: slow erosion, critical moment, intellectual reconstruction, external input

### Module 7: Synaptic Plasticity (Ch. 8) — Cross-cutting concern
- Surprise Score → plasticity multiplier (noradrenaline analog)
- Outcome-based Engram weight (dopamine analog)
- Stress flag → learning inhibitor (cortisol analog)
- Reconsolidation window after retrieval
- High-Plasticity Mode (flow state analog)
- **Implementation**: Not a Node, but a module that modulates strength values across all other nodes

### Module 8: Replay & Prediction Error (Ch. 9) — Integrated into Consolidation
- Nightly Consolidation Run as replay mechanism
- Prediction Error → Surprise Score mapping
- Internal prediction errors during consolidation (schema coherence check)
- Awake replay → retrieval as amplifier
- **Implementation**: Integrated into Consolidation Flow Phase 1 and Retrieval nodes

### Module 9: Constructive Memory Node (Ch. 10)
- Retrieval as reconstruction, not lookup
- Gap identification: known gaps, unknown gaps, outdated info
- Schema-based supplementation with explicit FACT/INFERENCE/GAPS separation
- Reconsolidation during retrieval
- **Node mapping**: `execute()` assembles knowledge picture, `post_process()` structures payload

### Module 10: Retrieval Architecture Flow (Ch. 11)
- 4 phases as 4 sequential nodes: SchemaActivation → EngramCandidates → AssociativeSpreading → ConstructiveAssembly
- 4 modes: Precision, Exploration, Analogy, Validation (state-derived)
- Mode auto-derived from Session state
- Context budget with 3-tier priority

### Module 11: Synaptic Tagging & Capture (Ch. 12) — Cross-cutting concern
- Context Tags as synaptic tags
- Surprise Score as PRP trigger
- Association window: session-anchored, mode-dependent
- Spillover: `surprise_score * linear_attenuation(temporal_distance)`, capped
- Bidirectional within window (retrospective association)
- **Implementation**: Module that modifies consolidation weights in BufferIngest and Consolidation nodes

### Module 12: Working Context (Ch. 13) — Part of Agent Loop
- Transient activation space during running Task
- Goal stack, active engrams, episodic buffer, inference layer
- 3-tier capacity management
- Context-drift detection (planned + unplanned)
- Serialization for interruption/resumption
- Session Engram at Task end
- **Implementation**: Managed within the Agent Loop Flow, not a standalone node

## Key Demo Scenarios (What the Video Shows)

### Scenario 1: Cross-Session Memory Recall
User asks about a topic discussed 3 sessions ago. Agent retrieves the relevant engram, provides the answer with context, and marks it as FACT (from engram) vs INFERENCE (schema-based supplement).

### Scenario 2: Timely Forgetting
An outdated preference (e.g., "use library v1.x") has decayed through non-retrieval. Agent surfaces that this memory is outdated and asks for confirmation instead of blindly using stale info.

### Scenario 3: Schema Evolution
After multiple interactions about similar topics, the agent has formed a meta-engram (schema). When a new query arrives, the schema proactively narrows the retrieval scope — faster and more accurate than brute-force search.

### Scenario 4: Constructive Retrieval with Gap Transparency
Agent is asked a question where engrams cover 70% of the answer. It explicitly reports: "Here's what I know (FACT), here's what I infer (INFERENCE from schema), and here's what I'm missing (GAP)."

### Scenario 5: Learning from Surprise
Agent makes a wrong prediction. The high Surprise Score triggers faster learning — the reconsolidation window opens, and the next interaction shows corrected behavior.

## Competitive Differentiation

What makes our project stand out vs. other Track 1 submissions:

1. **Not just RAG with persistence** — Most submissions will be "ChatGPT with a vector store". Ours is a neuroscience-grounded dual-store memory architecture with active consolidation, forgetting, and schema formation.

2. **Built in Rust with PocketFlow** — Shows serious engineering depth. Rust is uncommon in hackathons and signals production-quality intent. PocketFlow's graph-based flow architecture maps naturally to the engram pipeline.

3. **Constructive retrieval with transparency** — Others return raw documents. We reconstruct knowledge pictures with explicit FACT/INFERENCE/GAP markings.

4. **Active forgetting as a feature** — Most systems only accumulate. Ours actively decays, archives, and compresses — a quality mechanism, not data loss.

5. **Schema-based prediction** — The system doesn't just recall; it predicts what knowledge will be needed, narrowing the search space proactively.

6. **Full Qwen Cloud API utilization** — Chat, thinking mode, embeddings, reranking, structured output, function calling, MCP — demonstrating sophisticated API usage across all capabilities.

## Risk Mitigation

| Risk | Mitigation |
|---|---|
| Scope too large for timeline | Keep the MVP broad but shallow: ship all core mechanisms with simple implementations before deep optimization. |
| Alibaba Cloud unfamiliarity | Start deployment in Phase 1, not Phase 4. Use ECS + managed PostgreSQL + Qdrant on ECS — straightforward. |
| Qwen Cloud API learning curve | Chat and embeddings are OpenAI-compatible. Use `reqwest` with compatible-mode payloads first, then add native DashScope rerank. |
| Qwen endpoint mismatch | Treat chat/embeddings as compatible-mode calls, reranking as DashScope rerank calls, and structured extraction as a non-thinking pass after thinking-mode reasoning. |

## Appendix: Agent Memory Architecture — Implementation Extract

*Condensed from `docs/agent-memory.md` (3034 lines) — only implementation-relevant details.*

### Core Principle

**Complementary Learning Systems (CLS):** Two separate memory stores with a consolidation bridge between them. This is not a design preference — it is the only robust solution to Catastrophic Interference (new learning overwrites old knowledge).

- **Hippocampal System (fast):** Pre-Engram Buffer — learns immediately, sparse representations, no generalization, short-term buffer
- **Neocortical System (slow):** Engram Dictionary + Schema Store — learns through repeated consolidation, overlapping representations, enables generalization
- **Consolidation Bridge:** Nightly Consolidation Run — transforms episodic knowledge into structural knowledge

### Data Structures

#### Episode
```
episode = {
  action,       // what was executed
  context,      // what state was the system in
  outcome       // what was the actual result
}
```
`expected_outcome` lives in the active Session, NOT in the Episode.

#### Session (PFC State)
```
session = {
  current_expectation,   // what the agent expects as result
  current_mode,          // Exploration / Routine / Critical
  task_context           // active Task context
}
```
Without an open Session, a **Default Session** takes effect with neutral expectation and `mode = Exploration`.

**Session lifecycle for implementation:**
- `open_session(user_id, mode, task_context)` creates a durable `session_id`
- `update_session(session_id, expectation, mode, task_context)` records task drift and expectation changes
- `close_session(session_id, outcome)` triggers Session-end consolidation
- Parallel sessions are allowed, but every Episode must carry exactly one `session_id`; missing IDs route to a Default Session scoped to the caller

#### Engram Dictionary Entry
```
engram_entry = {
  id,                  // unique identifier
  embedding,           // semantic vector for similarity search
  tags,                // thematic markers
  strength,            // accumulated strength (increases through retrieval and replay)
  thalamus_scores,     // Novelty, Surprise, Task-Relevance, Valence at creation
  created_at,          // timestamp of creation
  last_accessed,       // last retrieval
  access_count,        // how many times the Engram was retrieved
  session_ref,         // reference to Session in which the Engram arose
  episodic_content_ref,// pointer to full content in OSS/PostgreSQL
  schema_refs          // optional Meta-Engram / schema links
}
```
An Engram is **distributed**: the Dictionary holds only the index + metadata; full content lives behind `episodic_content_ref`, abstracted pattern knowledge lives behind `schema_refs` / Meta-Engrams.

**No versioning** — Engrams are overwritten on each update (reconsolidation). Access history via `last_accessed` + `access_count`.

**Identity:** Determined by embedding similarity threshold (Pattern Sep/Comp decides new vs update).

**Retrieval loading:** Depending on context budget, retrieval can load only index metadata, full episodic content, or schema abstraction.

**Granularity hierarchy:**
- Episodic Engram (single consolidated Episode)
- Meso-Engram (compression of similar episodic Engrams)
- Schema Engram / Meta-Engram (abstracted structural knowledge, hippocampus-independent)

**Lifecycle:** Episode → Thalamus Filter → Pre-Engram Buffer (fragile) → Nightly Consolidation → Engram (consolidated) → repeated consolidation → Meso-Engram → Schema Engram. Decay/archive at any stage if strength is too low.

#### Pattern Entry (Pre-Engram Buffer)
```
pattern_entry = {
  pattern_hash,       // embedding-based fingerprint (ANN-compatible)
  embedding,          // vector stored in Qdrant pre_engram_buffer collection
  occurrences,        // number of activations since creation
  strength,           // accumulated strength value (0.0 – 1.0)
  first_seen,         // timestamp of first activation
  last_seen,          // timestamp of last activation
  context_tags,       // all contextual tags from contributing Episodes
  threshold,          // target value for Engram creation (domain-adaptive)
  decay_rate,         // modulated by valence_score and surprise_score
  source              // ACCUMULATED — marks origin for Source Monitoring
}
```

Stored in Qdrant `pre_engram_buffer`: `embedding` is the vector; all other fields are payload. Full episode text is referenced, not duplicated in the vector payload.

#### Meta-Engram (Schema Store)
```
meta_engram = {
  id,
  embedding,           // abstracted pattern vector
  tags,                // intersection of tags from source engrams
  strength,            // aggregated from cluster
  source_engram_ids,   // references to all source Engrams
  prediction_fields    // expected knowledge fields (for gap detection)
}
```

### Thalamus Filter (Ch. 2)

Evaluates each Episode BEFORE it enters the memory system. Lightweight, fast, upstream of expensive operations.

**4 parallel scores:**

| Dimension | Question | Origin |
|---|---|---|
| Novelty | Has this pattern been processed recently? | Engram Dictionary (Recency-Check) |
| Surprise | Does the outcome differ from the expectation? | `session.current_expectation` vs `episode.outcome` |
| Task-Relevance | Does the Episode relate to the current Task? | `session.task_context` |
| Emotional Valence | Did the Episode have a strong positive or negative outcome? | Valence assessment of `episode.outcome` |

Overall Score = weighted sum. `score >= relevance_threshold` → accepted; below threshold → discarded.

**Relevance threshold modulation by session mode:**
- Exploration → low threshold (more info enters)
- Routine → high threshold (only strong deviations)
- Critical Error → threshold = 0 (everything stored, like shock state)

This Thalamus relevance threshold is not the same as the Pattern Sep/Comp completion similarity threshold.

### Pre-Engram Buffer (Ch. 4)

Two complementary roles:
1. **Episodic Short-Term Storage:** Complete Episode refs held until Consolidation Run decides
2. **Pattern Accumulator:** Weak signals accumulate until threshold → Engram

**Accumulation logic:**
- Pattern already in Qdrant `pre_engram_buffer` (ANN cosine similarity > buffer similarity threshold): increase strength, update `last_seen`, supplement tags. Increase weighted by Episode's Surprise Score.
- New pattern: create entry with initial strength proportional to Thalamus Score.
- Strength exceeds buffer strength threshold → pass to Pattern Sep/Comp, buffer entry deleted after successful Engram create/update.

**Decay formula:**
```
new_strength = current_strength × e^(-decay_rate × days_inactive)
```
Decay rate modulated: high valence_score or surprise_score → slower decay.
Below minimum → deleted.

**Strength-proportional replay:** During Consolidation Run, stronger entries replayed more frequently. Can push borderline entries over threshold.

**Size management:** Decay primary. LRU eviction if budget exceeded (weakest + longest-inactive first).

### Pattern Separation / Completion (Ch. 5)

Decides: new Engram (Separation) or update existing (Completion).

**Decision process:**
1. **Sparse Embedding Search:** ANN (Approximate Nearest Neighbor) in Engram Dictionary
2. **Threshold Check:** Max similarity > Completion Threshold → Completion; else → Separation
3a. **Pattern Completion:** Existing Engram enriched — new tags added, strength increases. NOT overwritten.
3b. **Pattern Separation:** New Engram created with **kinship reference** to most similar existing Engram.

**Threshold convention:** Because Completion occurs when `max_similarity > completion_threshold`, a **higher** completion threshold makes Completion harder and biases toward Separation; a **lower** completion threshold makes Completion easier and biases toward Completion.

**Tie-breaking:** Engram with higher `strength` wins Completion. Genuine tie → Separation.

**Completion Threshold — 5 modulation levels:**
1. **Cholinergic (Mode):** Exploration → higher threshold (more separation); Routine → lower threshold (more completion)
2. **Engram Age:** Young → threshold rises (separation bias); Mature → threshold lowers (completion bias)
3. **Surprise Score:** High surprise → threshold rises (prefer separation)
4. **Similarity Gradient:** Clear single match → completion; diffuse across many → separation
5. **Adaptive Feedback:** Too many fragmentation-related retrieval misses → threshold lowers; too many false completions → threshold rises

**Kinship References:** Depth-1 only (direct pointer to most similar Engram at creation). Deeper traversal during Retrieval with reduced threshold.

### Nightly Consolidation Run (Ch. 6)

Three sequential phases. "Nightly" = functional metaphor, not clock-bound. Triggers: session-based (primary), threshold (overflow), time-based (fallback).

**Phase 1 — Pre-Engram Buffer Decay:**
- Apply decay formula to each entry
- Below minimum → delete
- Borderline entries → strength-proportional replay (probability = strength × session_ref weight)
- session_ref determines replay weighting: Critical Sessions or high task_relevance → elevated priority

**Phase 2 — Engram Strength Decay & Archiving:**

| State | Condition | Action |
|---|---|---|
| Active | Strength > active_threshold | No action |
| Weakened | archive_threshold < Strength ≤ active_threshold | Reduced retrieval weight |
| Archived | Strength ≤ archive_threshold | Move to Archive (deactivated, not deleted) |

Archived Engrams can be reactivated but don't burden normal retrieval.

**Phase 3 — Schema Compression:**
- **Incremental:** Only new Engrams + their nearest neighbors reclustered. Existing Meta-Engrams untouched.
- **Cluster ID:** Embedding similarity + shared Context Tags + frequently retrieved together.
- **Meta-Engram Creation:** Tag intersection + aggregated strength + references to source Engrams.
- **Source Engrams** degraded to instances (lower retrieval priority). Meta-Engram becomes primary access point.
- **3 interference prevention mechanisms:**
  1. Source Engrams retained as instances (can be explicitly loaded)
  2. Engrams with high Surprise scores excluded from compression (exceptions preserved)
  3. Reversible: poor Meta-Engram → dissolve, reactivate sources

**Quality control:** Adaptive Feedback Loop — Meta-Engrams with poor retrieval results lose strength → eventually archived.

### Schema Theory (Ch. 7)

**Schemas emerge from data, not predefined.** This is the reversal from classical computing.

**Three integration modes (after Piaget):**
1. **Assimilation:** New info fits existing schema → integrated, no structural change
2. **Accommodation:** New info almost fits → schema extended/adjusted
3. **Schema Violation:** Too different → new schema created

Maps directly to Pattern Sep/Comp: Assimilation/Accommodation = Completion; Violation = Separation.

**Four types of schema evolution:**
- Slow Erosion (counterexamples accumulate over time)
- Critical Moment (single extreme Surprise Score event)
- Intellectual Reconstruction (Consolidation Run Phase 3 / REM sleep analog)
- External Input (explicit human correction with high weight)

**Schemas as prediction engine:** Active schema generates expectations → restricts retrieval scope → reduces search space. Schema confirmed → strength up. Prediction error → schema update check.

### Synaptic Plasticity (Ch. 8)

**Cross-cutting module** — modulates how quickly and durably learning occurs.

| Neuro-modulator | AI Equivalent | Effect |
|---|---|---|
| Noradrenaline | Surprise Score as update multiplier | High surprise → Engrams learn faster from this error |
| Dopamine | Outcome-based Engram weight | Success → increase strength of active Engrams; Failure → decrease |
| Cortisol (acute) | Temporary attention increase | Short-term: slight plasticity boost |
| Cortisol (chronic) | Stress flag | Raises Engram creation threshold, prefers Completion over Separation, blocks Consolidation Run |
| Reconsolidation | Instability protocol after retrieval | Engram changeable until next episode or Consolidation Run |
| Flow state | High-Plasticity Mode | Increased multiplier, extended reconsolidation window, more frequent consolidation |

**Plasticity control:** Separate from completion similarity threshold. New contexts and positive feedback increase learning-rate/replay priority; stress raises Engram creation thresholds and suppresses consolidation; mature stable Engrams get lower update volatility.

**Self-regulation:** If average strength variance across Engrams exceeds threshold → High-Plasticity Mode auto-deactivates.

**Dopamine ceiling:** Single positive outcome increases strength by at most a configurable % of current strength. Prevents overfitting.

### Replay & Prediction Error (Ch. 9)

Integrated into Consolidation Run + Retrieval — not a separate module.

- **Replay = Consolidation Run** — reactivates Engrams, strengthens frequent ones, weakens inactive
- **Prediction Error = Surprise Score** — positive → strengthen + raise replay priority; negative → destabilize + open reconsolidation; none → minimal confirmation
- **Internal Prediction Errors during consolidation:** Engrams tested against schema → consistent → strong consolidation; slightly deviant → normal; strongly deviant → dampened, marked as exception
- **Awake Replay = Retrieval:** Every retrieval minimally increases strength + access_count

### Constructive Memory (Ch. 10)

Retrieval is **reconstruction**, not lookup. Four steps:

1. **Engram Activation:** Multiple Engrams activated, weighted by: semantic similarity, tag overlap, strength, recency, kinship references. Partial activation possible (dampen irrelevant parts).
2. **Gap Identification:** Which Task aspects NOT covered by activated Engrams?
   - Known Gap: system knows info is missing → schema supplementation or explicit uncertainty
   - Unknown Gap: missing info not recognized → structural risk
   - Outdated: Engram may be obsolete → recency flag
3. **Schema-based Supplementation:** Known gaps filled by active schema — marked as INFERENCE, not FACT.
4. **Reconstructed Knowledge Picture:** Contextualized compilation with three explicit fields:
   - `facts` — directly verifiable from Engrams
   - `inferences` — derived from schema expectation, with source
   - `gaps` — known gaps without schema coverage (including "structural uncertainty")

**Every retrieval is a learning moment:** Reconsolidation window opens; if Task provides new info → Engram enriched.

### Retrieval Architecture (Ch. 11)

**4 phases (sequential):**

1. **Schema Activation:** Identify most similar Meta-Engram → generate expectation list of relevant Engram types/tags
2. **Engram Candidates:** ANN search + Relevance Scoring (semantic similarity, tag overlap, schema prediction match, strength, recency, outcome weight)
3. **Associative Spreading:** From top candidates, spread via kinship references with dampened weight (distance 1 = 0.6, distance 2 = 0.36, etc.). Cross-schema spreading enabled for analogy.
4. **Constructive Assembly:** Assemble knowledge picture per Ch. 10.

**4 modes (auto-derived from Session):**

| Mode | Trigger | Behavior |
|---|---|---|
| Precision | Routine mode, known Task, low Surprise | Tight ANN, shallow spreading, high tag weight |
| Exploration | Exploration mode, unknown Task | Broad ANN, deep spreading, high schema weight |
| Analogy | Low tag overlap + high embedding similarity | Cross-schema spreading |
| Validation | High Surprise + set expectation | Load counterexamples, CA1 mismatch detection |

**Context budget:** 3 tiers — Tier 1 (full Engrams), Tier 2 (Meta-Engrams instead of sources), Tier 3 (tags + embedding only). N = session-mode-dependent.

**Retrieval as learning:** Access count increases, reconsolidation window opens, retrieval quality logged.

### Synaptic Tagging & Capture (Ch. 12)

**Cross-cutting module** — temporal association between Episodes.

**3 core statements:**
1. Temporal proximity: events close in time reinforce each other's consolidation (even if content-unrelated)
2. Asymmetric: strong event can "pull along" weak ones; reverse doesn't work
3. Tag window: configurable association radius; beyond window → no linking

**Mapping:**
- Context Tags = synaptic tags (mark Episode as "plasticity desired", temporally bound)
- Surprise Score = PRP trigger (high surprise → consolidation weight generated)
- Spillover: weak Episodes near a high-surprise Episode receive elevated consolidation weight

**Association window:**
- Session-anchored: no STC across Session boundaries
- Within Session: mode-dependent (Routine = minutes; Exploration = entire Session)
- Bidirectional: Episodes before AND after the high-surprise event benefit

**Spillover formula:**
```
spillover = surprise_score_A × linear_attenuation(temporal_distance)
```
Linear: max at zero distance, zero at window boundary. Capped by `max_spillover_cap`.

**Two paths to permanent consolidation:**
- Buffer path: weak signal repeats → accumulation → threshold → Engram
- STC path: weak signal + temporal proximity to strong event → spillover → Engram
Both complementary.

### Working Context (Ch. 13)

**Transient activation space** during a running Task — the PFC analog.

**Distinct from Session:** Session = overarching interaction frame; Working Context = Task-specific within Session. One Session can have multiple sequential Working Contexts.

**Structure:**
- **Goal Stack:** Current goal + sub-goals. Defines search space for retrieval.
- **Active Engrams:** Loaded from Dictionary with activation weight. Frequently referenced → weight up; unreferenced → weight down → eviction.
- **Episodic Buffer:** Raw observations of current Task (tool calls, results, errors, decisions).
- **Inference Layer:** Active schema-based inferences, marked as inferences not facts.
- **Context Metadata:** Task ID, start time, active tags, stress flag, Session reference.

**3-tier capacity:**
- Tier 1 (full slots): Goal stack + highest-weight Engrams. Never evicted during Task.
- Tier 2 (half slots): Medium-weight Engrams as Meta-Engrams. Promotable/degradable.
- Tier 3 (quarter slots): Low-weight Engrams — tags + embedding only. First to evict.

**Consolidation at Task End:**
1. Episodic Buffer → complete Episode → Pre-Engram Buffer
2. Active Engrams: increase access_count, open reconsolidation window
3. Outcome signal: Surprise Score colors involved Engrams
4. Goal Stack + Task Encoding → **Session Engram** (for fast context restoration on next similar Task)

**Context-drift detection:**
- Planned drift: goal update → auto re-evaluate all active Engram tiers
- Unplanned drift: average activation score falls below threshold → Context-Refresh (re-run Retrieval Phase 1+2). High Surprise always triggers Refresh.

**Interruption/resumption:** Serialize (goal refs + Engram IDs + weights + buffer snapshot + metadata — no full Engram contents). Resume: reload from Dictionary (may have been updated by Consolidation Run).

**Multi-Task:** Each Task gets own Working Context. Budget per Context, shared Dictionary/Schema. On switch: serialize active, deserialize target.

## 13 Mechanisms (Condensed)

### Ch. 1 — CLS
Two systems, not one. Fast buffer + slow dictionary. Consolidation bridge between them. This is the architectural foundation.

### Ch. 2 — Thalamus Filter
Gatekeeper. 4 parallel scores: **Novelty** (from Dictionary), **Surprise** (expectation vs outcome), **Task-Relevance** (from Session), **Emotional Valence** (from outcome). Weighted sum vs relevance threshold: Exploration=low, Routine=high, Critical=zero. This is distinct from Pattern Sep/Comp's completion similarity threshold.

### Ch. 3 — Memory Engrams
Engrams are distributed: Dictionary holds index, episodic storage holds content, Schema store holds abstractions. No versioning — overwritten on reconsolidation. Identity = embedding similarity threshold. Granularity: episodic → meso → schema.

### Ch. 4 — Pre-Engram Buffer
Dual role: (1) hold complete Episode refs until consolidation, (2) accumulate weak signals in Qdrant `pre_engram_buffer`. Decay: `strength × e^(-decay_rate × days_inactive)`, modulated by valence/surprise. Strength-proportional replay for borderline entries. LRU eviction as safety net.

### Ch. 5 — Pattern Separation / Completion

Convention: higher completion threshold means more Separation; lower means more Completion. Threshold modulated by: mode, engram age, surprise score, similarity gradient, adaptive feedback. Kinship references = Depth-1 pointers for associative retrieval.

### Ch. 6 — Nightly Consolidation Run
3 phases: (1) Buffer decay + replay, (2) Engram strength decay → active/weakened/archive, (3) Schema compression — cluster similar Engrams → Meta-Engram. Incremental (only new + neighbors). Reversible. Source Engrams retained as instances.

### Ch. 7 — Schema Theory
Schemas **emerge from data**, not predefined. 3 modes: Assimilation (fits), Accommodation (adjust), Violation (new schema). Schema as prediction engine — generates expectations, narrows retrieval scope. Evolution: erosion, critical moment, reconstruction, external input.

### Ch. 8 — Synaptic Plasticity
Cross-cutting. Surprise → learning multiplier (noradrenaline). Success → strengthen active Engrams (dopamine, with ceiling). Stress flag → inhibit learning, prefer Completion, block consolidation. Reconsolidation window after retrieval. High-Plasticity Mode (flow analog) with self-regulation.

### Ch. 9 — Replay & Prediction Error
Integrated into Consolidation + Retrieval. Replay = Consolidation Run. Prediction Error = Surprise Score. Internal schema coherence check during consolidation. Retrieval = awake replay (increases strength).

### Ch. 10 — Constructive Memory
Retrieval = reconstruction, not lookup. 4 steps: (1) Activate multiple Engrams, (2) Identify gaps, (3) Fill known gaps with schema inferences, (4) Assemble knowledge picture with 3 fields: **facts**, **inferences**, **gaps**. Every retrieval = potential learning (reconsolidation).

### Ch. 11 — Retrieval Architecture
4 phases: Schema Activation → Engram Candidates → Associative Spreading → Constructive Assembly. 4 modes (auto from Session): Precision (routine), Exploration (unknown), Analogy (cross-schema), Validation (counterexamples). 3-tier context budget.

### Ch. 12 — Synaptic Tagging & Capture (STC)
Cross-cutting. Weak Episode + temporal proximity to strong Episode → spillover consolidation weight. Formula: `surprise_score × linear_attenuation(temporal_distance)`, capped. Window = session-anchored, mode-dependent. Bidirectional (retrospective). Complements Buffer accumulation path.

### Ch. 13 — Working Context
Transient PFC workspace per Task. Goal stack + active Engrams + episodic buffer + inference layer. 3-tier capacity (full/half/quarter slots). At Task end: Episode → Buffer, Engrams → access_count++, Session Engram saved. Context-drift detection: goal updates (planned), score monitoring (unplanned). Serialization for interruption/resumption.
